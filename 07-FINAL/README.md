# 07-FINAL

Board pack only.

**Assessment records and certificates are deliberately NOT in this repository.**

This repo is public. Intern assessment records, marks, feedback and
certificates are personal data about identifiable people and do not belong in
a world-readable repository. They live in a separate private repository,
`SYCOM-INTERNSHIP-ASSESSMENT`, visible to the CISO and mentors only.

If you find yourself about to commit a mark, a rubric score, a feedback note
or a named certificate here, stop. It goes in the other repo.

- `Board-Pack` — the week-4 board session materials the interns produce

## How the board pack gets here

The cohort does **not** write the board pack in this repository. It is drafted
in a private repository that every intern and every mentor can see: for
Pilot 1, `sycom-academy/pilot1-board-pack`. The reason is in
[`CONSENT-AND-PUBLICATION.md`](../00-ADMIN/CONSENT-AND-PUBLICATION.md) §9,
item 5: the pack is published with no individual authors, so that nobody's
participation choice shows in its history.

When the pack is final (Inject 09 deadline, W4 D3 09:00), one mentor publishes
it:

1. Download the final files from the drafting repository (**Code → Download
   ZIP**).
2. In an ordinary clone of this repository, copy them into
   `07-FINAL/Board-Pack/`.
3. Commit them under the mentor's own name and open a pull request. Another
   mentor reviews and merges it as usual.

**Copy the files. Never move the history.** Every commit in the drafting
repository carries its author's account. None of the following may ever be
done, because each one publishes every contributor's name permanently:

- merging, pushing or pulling the drafting repository into this one
- adding the drafting repository as a git remote of this one
- **Import repository**, forking, transferring, or making the drafting
  repository public

Before merging, the reviewing mentor checks the pack itself:

- no author list, "prepared by" line, or individual names
- no links to, or file paths inside, any private repository; cite sources by
  workstream and deliverable instead (for example, "GRC risk register")
